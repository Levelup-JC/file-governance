# Obsidian 索引

## 一、职责边界

Obsidian 管索引和纯笔记，不管备份。多设备同步由用户自己决定做法，这不属于本规范；也不要对库执行 git、同步或推送。

## 二、索引单位是 GitHub 仓库

不以本地路径为单位。项目夹会从 `【2】DO处理中/` 搬进 `【3】DONE归档区/`，存档久了还可能改项目名，写成绝对路径必然失效。

Obsidian 只能读本地磁盘，读不了远端仓库。所以索引的前提是仓库已经 clone 到本地：

1. `gh repo clone owner/name ~/Documents/repos/name`
2. 在 Obsidian 里用「Open folder as vault」打开，或把目录放成主库的子目录
3. MOC 页里只写 `repo: owner/name`，本地位置由「项目总览」统一记

不建软链接。软链接在仓库搬走或重 clone 后必断，且 Obsidian 索引会跟着出错。

## 三、项目总览

主库根目录放一张 `项目总览.md`，或做成一张 Base。每个项目一行。

```markdown
# 项目总览

| 项目 | 仓库 | 当前本地路径 | 状态 | 正本 |
|---|---|---|---|---|
| 上海财经分享 | `<你的账号>/sufe-talk` | `~/Desktop/【2】DO处理中/02-上海财经分享/` | 进行中 | `1-产出/分享稿.md` |
| 文件治理 skill | `<你的账号>/file-governance` | `~/Desktop/【2】DO处理中/09-通用/` | 进行中 | `1-产出/SKILL.md` |
| 黄仁勋热点花絮 | 无（纯媒体） | `~/Desktop/【3】DONE归档区/…/` | 已归档 | `1-产出/成片.mp4` |
```

四条规则：

- 只改「当前本地路径」一格，其余不随搬家变。
- 纯媒体项目没有仓库，仓库列写「无」，正本靠本地路径定位。
- 状态只有三种：进行中、暂停、已归档。
- 一张表不超过 60 行；超了就按年份拆成 `项目总览-2026.md`。

## 四、MOC 页

每个有笔记的项目一张，放主库 `项目/` 目录下。

```markdown
repo: <你的账号>/sufe-talk
状态: 进行中
正本: 1-产出/分享稿.md

# 上海财经分享 MOC

讲 WorkBuddy 怎么把想法做成产品，面向非技术学生。

## 关键笔记
- [[WorkBuddy 的三个使用场景]]
- [[现场问答整理]]

## 外部链接
- 幻灯片：[链接]
```

规则：

- 第一行 `repo:` 是索引锚点，不要写成绝对路径。
- 不超过 100 行，层级不超过 4 层。超过就说明该拆。
- 笔记满 10 条再建 MOC，不要提前建空壳。
- 不复制正文进来。MOC 只放链接和一句话说明。

## 五、纯笔记型项目

读书笔记、灵感、复盘这类没有正本文件的项目，正文才住在库里。

- 直接在库里建目录写笔记，不需要 `1-产出/` 那套桌面结构。
- 项目日志写在笔记目录旁边，同样一个项目一份。
- 「项目总览」里仓库列写「无（纯笔记）」，当前本地路径写库内相对路径。

## 六、搬家与归档

项目从 `【2】DO处理中/` 移到 `【3】DONE归档区/` 时，按顺序做：

1. 移动文件夹。
2. 改「项目总览」里的「当前本地路径」一格。
3. 改 MOC 页的「状态」为已归档。
4. 更新 `~/Desktop/桌面索引.md`，并在末尾搬迁对照表里加一行旧路径 → 新路径。
5. 检查有没有别的项目 README 里写着旧路径，一并改掉。

MOC 页里的 `repo:` 不动，所以库里的索引在搬家时几乎不需要改——这是选仓库作索引单位的全部理由。

## 七、库外不要有第二份

库里写了一份笔记、桌面项目里又存了一份同内容文档，就是两份正本。判断方法：这份内容如果被修改，需要改几个地方？答案大于 1 就是错的，留一份，另一处写链接。
