# 项目日志模板

一个项目只有一份，放项目根目录 `项目日志.md`。最新的改动写在最上面。

```markdown
# 项目日志：<项目名>

## 复盘（按阶段更新，用户宣布项目结束后停止）

### 阶段一：<名称>（YYYY-MM-DD 起）

- 收获：
- 教训：
- 下次要改：

### 阶段二：<名称>

## 修改记录（倒序）

### 2026-11-26 建立目录结构

- 改了什么：按治理规范建出 1-产出 / 2-草稿 / 3-素材 / 4-过程 / 9-归档，写了 README 和 .gitignore。
- 改了哪里：项目根目录；存档 `a1b2c3d`。
- 为什么：项目原先文件散在桌面根目录，找不到正本。
- 来源：无。

### 2026-11-25 导入素材

- 改了什么：把 12 个原片从 `~/Downloads` 移进 `3-素材/采访/`，未改名。
- 改了哪里：3-素材/。
- 为什么：原片要和成片分开，素材不进存档。
- 来源：`https://example.com/interview-source`；NAS `影视仓库/2026/interview/`。
```

## 四条填写规则

1. **四栏都要写全。** 改了什么、改了哪里、为什么、来源。缺「为什么」的记录一个月后就没用了。
2. **「改了哪里」写路径。** 代码类项目链到 commit 或 PR 号，方便读档。
3. **「来源」必填于素材和成片相关的记录。** 素材和 `1-产出/` 的成片不进 git，日志是唯一能追回原始出处的地方，写原始链接或 NAS 路径。
4. **一条记录一件事。** 一次整理动了十个项目，就在各自项目的日志里各写一条，不要写成跨项目的流水账。

## 复盘怎么写

- 每个阶段结束时写一次，不按天写。
- 三段：收获、教训、下次要改。教训和「下次要改」写成能执行的句子，例如「下次先确认交付格式再剪」。
- 用户宣布项目结束后，复盘停止更新，日志整体进入只读状态；项目移进 `9-归档/`，并在桌面索引里把状态改成「已归档」。
