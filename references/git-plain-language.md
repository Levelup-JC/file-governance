# 白话存档规则

## 一、对用户说什么

用户不关心 git 术语。每次操作后用一行白话告诉用户发生了什么。

| 内部动作 | 对用户说 |
|---|---|
| `git commit -m "..."` | 已存档：「这次做了 X」 |
| `git push` | 已存到 GitHub：「已备份到 GitHub」 |
| `git checkout <sha> -- <path>` | 已读档：「已退回到 11 月 25 日那版」 |
| `git log --oneline` | 翻了下存档记录：「最近三次存档分别是……」 |
| `.gitignore` | 「这几类文件不进存档」 |

存档说明本身也用中文写，格式仍是 Conventional Commits（`feat` / `fix` / `docs` / `refactor` / `chore`），前缀是给工具看的，后面那句给用户看。

## 二、什么时候存档

- **改之前存一次。** 尤其是批量移动、批量改名、重构。
- **能跑通后存一次。** 这是用户最需要的存档点：「上次还能跑」。
- **每完成一步整理存一次。** 存量整理时，每归完一个项目就存一次。
- **不要为了存档而存档。** 一次会话存三到五次足够。

## 三、哪些东西不进存档

| 类别 | 进存档？ | 放哪 |
|---|---|---|
| 代码、脚本、配置 | 进 | 项目根目录 / `1-产出/` |
| 字幕、文案、脚本稿 | 进 | `2-草稿/` 或 `1-产出/` |
| `项目日志.md`、README | 进 | 项目根目录 |
| `4-过程/plan/` 计划文档 | 进 | `4-过程/plan/` |
| `3-素材/`（原片、图、音） | 不进 | 同步 NAS |
| `1-产出/` 里的成片（视频、大图） | 不进 | 同步 NAS |
| `4-过程/temp/` | 不进 | 用完即清 |
| `.DS_Store`、`*.log`、`node_modules/` | 不进 | —— |

素材和成片不进存档不是偷懒：Git 存不下大二进制，反复改版本会把仓库撑爆。代价是没有版本历史，所以**每个用到素材和成片的地方，必须在项目日志的「来源」一栏写原始链接或 NAS 路径**。

## 四、文件大小阈值

- 单文件超过 **50 MiB**：抓出来提醒用户，建议改走 NAS。
- 单文件超过 **100 MiB**：拒绝推送，GitHub 会直接报错。先移到 NAS，再从仓库移除。
- 仓库总量接近 **1 GiB**：提醒用户该归档了。

用 `git ls-files -z | xargs -0 du -h | sort -h | tail -20` 查最大的文件。

## 五、不用 Git LFS

LFS 的免费额度是 1 GiB 存储和每月 1 GiB 带宽，团队或个人视频项目几天就用完，超了要绑卡。既然素材本来就要进 NAS，就不要为它额外维护一套 LFS 存储。

## 六、代码和媒体混在一个项目

一个项目夹，一个 git，建在项目根目录。不要为素材单独开仓库。

- 素材和成片放在被忽略的目录里，本地存在、NAS 有备份、git 不管。
- 同一个人从另一台机器拿项目时，clone 只拿到代码和文档，素材要另外从 NAS 同步。**README 里必须写清素材在 NAS 的哪个路径**，否则换机器就断档。

```
项目夹/
├── .git
├── README.md            ← 写清素材在 NAS 的路径
├── 项目日志.md
├── .gitignore           ← 忽略 3-素材/、成片、temp
├── 1-产出/              ← 代码进存档；成片不进
├── 2-草稿/
├── 3-素材/              ← 不进存档
└── 4-过程/
```

## 七、分支

默认不用分支。个人项目一个人干活，分支只在两种情况下用：要让 AI 大改又不敢动主线；要同时试两个方案。用完合回去，别留一堆死分支。

## 八、推送前检查清单

推之前逐条确认，任何一条不过就不推：

1. 已经问过用户，用户同意了。
2. 仓库是私有的（除非用户明确要公开）。
3. `git status` 里没有被 `.gitignore` 漏掉的大文件或密钥。
4. `.env`、`credentials.json`、`*.pem`、`*.key` 不在待推列表里。
5. 项目日志里这次改动有记录。
